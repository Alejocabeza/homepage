## 3. Implementation Approach

### Recommended: JSON Translation Files + Astro i18n Routing

**Rationale**:
- Astro 5.x has built-in i18n routing via `i18n` config
- Keeps current page structure intact
- JSON files are human-readable and easy to maintain
- Works with SSR output mode (`output: "server"`)

### Alternative Considered: Pure Query Param / Cookie

- Simpler to implement but worse SEO (duplicated content)
- Less maintainable long-term
- **Rejected** for this portfolio

### File Structure

```
src/
├── i18n/
│   ├── index.ts          # i18n utility functions
│   ├── es.json           # Spanish translations (default)
│   └── en.json           # English translations
```

## 4. URL Strategy

### Option A: `/en/` Prefix (Recommended)

| URL | Locale | Description |
|-----|--------|-------------|
| `/` | Spanish (default) | Redirects to `/es/` or serves Spanish version |
| `/es/` | Spanish | Explicit Spanish root |
| `/es/projects/` | Spanish | Spanish projects page |
| `/en/` | English | English root |
| `/en/projects/` | English | English projects page |

**Advantages**:
- ✅ Best SEO: Search engines see distinct URLs per language
- ✅ Clean URLs: `/en/projects` is readable and standard
- ✅ Astro built-in support via `i18n.routingStrategy`
- ✅ Canonical tags can distinguish languages

**Disadvantages**:
- Requires restructuring `src/pages/` into locale subdirectories

### Option B: Subdomain

| URL | Locale |
|-----|--------|
| `alejandrocabeza.dev` | Spanish |
| `en.alejandrocabeza.dev` | English |

- **Rejected**: Adds DNS complexity, requires additional hosting setup

### Option C: Query Parameter

| URL | Locale |
|-----|--------|
| `/?lang=en` | English |

- **Rejected**: Bad SEO (duplicate content), poor UX, not bookmark-friendly

## 5. Language Switcher

### Location: Header (Navigation Bar)

**Design**:
- Add language switcher as a dropdown in the header
- Position: Right side of navigation, after existing links
- Format: `ES | EN` toggle or globe icon + dropdown

**Implementation**:

```astro
<!-- src/shared/components/header.astro -->
<div class="flex items-center gap-2 ml-4 pl-4 border-l border-border">
  <a 
    href={switchToLangUrl('es')} 
    class:list={["text-sm", currentLang === 'es' && "font-bold"]}
  >
    ES
  </a>
  <span class="text-text-muted">|</span>
  <a 
    href={switchToLangUrl('en')} 
    class:list={["text-sm", currentLang === 'en' && "font-bold"]}
  >
    EN
  </a>
</div>
```

### Behavior

1. **Click**: Navigates to the same page in the selected language
2. **Persistence**: Store preference in cookie or localStorage
3. **Default**: Detect from `Accept-Language` header if no preference stored
4. **Visual feedback**: Current language is highlighted/bold

### Cookie/Storage

```
Cookie: locale=es (or locale=en)
```

## 7. Technical Notes

### 7.1 Astro Configuration

Add to `astro.config.mjs`:

```javascript
export default defineConfig({
  site,
  output: "server",
  i18n: {
    defaultLocale: "es",
    locales: ["es", "en"],
    routing: {
      prefixDefaultLocale: false, // /es/ is default, not shown
    },
  },
  // ... existing config
});
```

### 7.2 Page Restructuring

1. Move `src/pages/index.astro` → `src/pages/es/index.astro`
2. Create `src/pages/en/index.astro` with English content
3. Create `src/pages/index.astro` that redirects based on detected locale
4. Repeat for `/projects/` and `/blog/` pages

### 7.3 cv.json Bilingual Strategy

**Option A**: Single cv.json with all content in both languages

```json
{
  "basics": {
    "name": "Alejandro Cabeza",
    "heroSummary": {
      "es": "<strong>Laravel Specialist</strong>...",
      "en": "<strong>Laravel Specialist</strong>..."
    }
  }
}
```

**Option B**: Separate data files per language

```
src/data/
├── cv.es.json
└── cv.en.json
```

**Recommended**: Option A (single file) for simplicity, with nested language objects.

### 7.4 Language Detection Priority

1. URL path (`/en/` prefix)
2. Cookie stored preference
3. `Accept-Language` HTTP header
4. Default locale (`es`)

### 7.5 SEO Requirements

- Add `<link rel="alternate" hreflang="es" href="https://..." />` tags
- Add `<link rel="alternate" hreflang="en" href="https://..." />` tags
- Update sitemap to include both language variants
- Ensure canonical tags point to language-specific URLs

## 8. Success Criteria

### Functional Requirements

- [ ] User can switch between Spanish and English via header switcher
- [ ] URL reflects selected language (`/es/` or `/en/`)
- [ ] All UI labels update on language switch
- [ ] Section headings update on language switch
- [ ] CTA buttons update on language switch
- [ ] Availability badges update on language switch
- [ ] Project status badges update on language switch
- [ ] Meta tags (title, description) update on language switch
- [ ] Language preference persists across sessions (cookie)
- [ ] Browser's `Accept-Language` header is respected on first visit

### SEO Requirements

- [ ] Both `/es/` and `/en/` are crawlable
- [ ] `hreflang` tags are present
- [ ] Sitemap includes both language variants
- [ ] Canonical tags are language-specific

### Technical Requirements

- [ ] Astro i18n routing configured
- [ ] Translation files in `src/i18n/`
- [ ] i18n utility functions work with SSR
- [ ] No build errors after implementation
- [ ] All existing functionality preserved
